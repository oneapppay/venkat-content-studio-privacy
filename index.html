Privacy policy

Venkat Yanapothula · Content Studio · November 20, 2026

This policy describes the local Content Studio that signs in to LinkedIn and can publish posts for that one member.

Who operates it

Venkat Yanapothula operates the studio on his own computer. Questions about this policy can be sent to ops.venkat@gmail.com.

LinkedIn permissions

The LinkedIn sign-in request asks only for these permissions:

  • openid and profile, to identify the member who approves the connection.
  • w_member_social, to create a post for that member.

The studio does not request an email address. It does not call LinkedIn comment, reaction, invitation, or message APIs.

Personal data

After approval, the studio reads the member id and display name from LinkedIn's user-info endpoint. It also stores the access token LinkedIn returns, the token expiry, the granted scope, and a refresh token only when LinkedIn includes one.

Where tokens are stored

Tokens stay on the operator's computer in data/connection.enc, encrypted with AES-256-GCM. The encryption key is the local STUDIO_TOKEN_KEY value or the local data/token.key file. Tokens are not written into git, browser storage, or application logs. The client secret stays in the local .env file, which git ignores.

Publishing

A post is sent only for content prepared in this studio, and only after the member has connected the account. The post can include text and an image. LinkedIn then handles that post under LinkedIn's own terms and privacy policy. Automatic publishing of the other prepared technical posts stays off unless the operator turns that control on.

Disconnecting

Disconnect asks LinkedIn to revoke the token, deletes the encrypted connection file, and turns automatic publishing off.

Retention and sharing

The local connection remains until the operator disconnects or deletes the studio data directory. The studio does not sell this data and does not send the token to another service.
